1. これは何?

OBS で YouTube 配信を開始すると、自動的に配信タイトルと配信URLを埋め込んだ X (旧Twitter) の投稿作成画面がブラウザで開くツールです。
最後の「ポストする」ボタンだけは、内容を確認してから自分の手で押します。
X や YouTube の公式 API(サービスへの事前登録が必要な仕組み)は使わないため、面倒な登録作業は不要です。

できることできないこと
配信開始で自動的に投稿画面が開く / タイトルとURLが入力済み 投稿ボタンを自動で押すこと / X にログインしていない状態での投稿

2. 仕組み(図1)

配信を開始してから投稿画面が開くまでの流れは次の通りです。最後の一手だけが人の作業です。

※画面はイメージです。実際の表示とは異なる場合があります。

3. 必要なもの

  • Windows 11
  • Python 3.12 以上
  • OBS 28 以上
  • ブラウザで X にログイン済みであること
  • YouTube チャンネルのハンドル(@ から始まる名前。例: @your_handle)

4. 手順1: Python のインストール

  1. python.org から Python 3.12 以上のインストーラをダウンロードします。
  2. インストーラを起動したら、「Add python.exe to PATH」にチェックを入れてからインストールを進めます(下図の赤枠部分)。これを忘れると後の手順でコマンドが動きません。

※画面はイメージです。実際の表示とは異なる場合があります。

インストールが終わったら、PowerShell を開いて以下を実行し、バージョンが表示されることを確認してください。

python --version

5. 手順2: ツールの準備

  1. PowerShell を開きます(スタートメニューで「PowerShell」と検索)。
  2. 以下を1行ずつ実行します。
cd <展開したフォルダ>\alternatives\python
pip install -r requirements.txt

pip(Python のライブラリを追加するコマンド)がツールの動作に必要な部品を自動でダウンロード・インストールします。

6. 手順3: OBS の WebSocket を有効化

本ツールは OBS の WebSocket(OBS が外部のプログラムに配信状態を伝えるための通信の仕組み)機能を使って、配信開始のタイミングを検知します。

  1. OBS のメニューから 「ツール」→「WebSocket サーバー設定」を開きます。
  2. 「WebSocket サーバーを有効にする」にチェックを入れます(下図の赤枠部分)。
  3. サーバーポートは既定の 4455 のままで構いません。
  4. 「認証を有効にする」をオンにした場合は、「サーバーパスワード」欄に表示されているパスワードを覚えておきます。

※画面はイメージです。実際の表示とは異なる場合があります。

ヒント
パスワードを設定した場合は、次の手順4で作成する config.json の obs.password にそのパスワードを書き込みます。パスワードを設定していない場合は空文字 "" のままで構いません。

7. 手順4: 設定ファイルを作る

  1. エクスプローラで G:\workspace\projects\video\youtube-live-tweet\python フォルダを開きます。
  2. config.example.json を右クリックし、「コピー」→ 同じフォルダ内に「貼り付け」します(config.example.json のコピー のようなファイルができます)。
  3. そのコピーを右クリックして「名前の変更」を選び、config.json に変更します。
  4. config.json をメモ帳などのテキストエディタで開き、内容を編集します。
{
  "obs": { "host": "localhost", "port": 4455, "password": "" },
  "youtube": { "channel": "@your_handle" },
  "tweet": {
    "text": "配信はじめました！\n{title}",
    "include_url": true
  },
  "resolve": { "retry_interval_sec": 5, "timeout_sec": 120 },
  "fallback_open_when_unresolved": true
}
項目説明
obs.host / obs.portOBS WebSocket サーバーのホスト・ポート。通常は変更不要(ポートは手順3で確認した番号)。
obs.passwordOBS WebSocket サーバーのパスワード。手順3で設定していなければ空文字 "" のまま。
youtube.channel監視対象チャンネル。@handle 形式、または UC... のチャンネルID形式。調べ方は下記参照。
tweet.text投稿文のテンプレート。{title}(配信タイトル)・{url}(配信URL)のプレースホルダが使えます。
tweet.include_urltrue の場合、投稿画面の URL カードに配信URLを渡します(text 内の {url} にも展開されます)。
resolve.retry_interval_secYouTube 側の反映待ちのリトライ間隔(秒)。
resolve.timeout_secリトライを諦めるまでの時間(秒)。
fallback_open_when_unresolvedタイムアウトしてもライブ情報が取得できなかった場合に、タイトル空・チャンネルの /live URL で投稿画面を開くかどうか。

youtube.channel の調べ方

ブラウザで自分の YouTube チャンネルページを開き、アドレスバーの URL を確認します。 https://www.youtube.com/@xxxx のような形になっているので、@xxxx の部分をそのまま youtube.channel に書きます。

※画面はイメージです。実際の表示とは異なる場合があります。

注意
  • tweet.text の中で { や } をプレースホルダではなく普通の文字として使いたい場合は、{{ と }} のように2重にして書いてください。
  • JSON ファイルは書き方のルールが厳密です。最後の項目の後にカンマを付けないこと、true / false にはクォート(引用符)を付けないことに注意してください("true" ではなく true)。

8. 手順5: 動作確認

実際に配信中の状態で、PowerShell から以下を実行すると、1回だけ投稿画面が開きます(OBS を起動していなくても試せます)。 

python main.py --test

※画面はイメージです。実際の表示とは異なる場合があります。

ヒント
配信していない状態で --test を実行した場合、resolve.timeout_sec(既定120秒=2分)だけ待ってからライブ情報が取得できず、fallback_open_when_unresolved が true ならタイトル空・チャンネルの /live URL で投稿画面が開きます。

9. 手順6: ふだんの使い方

  1. run.bat をダブルクリックします。黒い画面(コンソール)が開くので、そのまま出しっぱなしにしておきます。
  2. OBS より先に起動しても問題ありません。OBS が起動していない間は自動的に再接続を試み続けます。
  3. 配信を開始すると、数十秒後に自動でブラウザに投稿画面が出ます。
  4. 内容を確認して「ポストする」を押します。

終了するときは、黒い画面をクリックして Ctrl+C を押すか、ウィンドウを閉じてください。

10. 手順7(任意): Windows 起動時に自動で開始

  1. Win + R を押し、shell:startup と入力して Enter を押します。スタートアップフォルダが開きます。
  2. run.bat を右クリックして「ショートカットの作成」を選びます。
  3. 作成されたショートカットを、開いておいたスタートアップフォルダに移動します。

これで Windows にログインするたびに、自動的に監視が始まります。

11. 困ったときは

症状原因対処
黒い画面に「OBS WebSocket に接続できません」が繰り返し出る OBS が起動していない、または WebSocket が無効/ポート・パスワードが違う 手順3を確認してください。OBS を起動する前であれば正常な表示です(起動すれば自動的に接続します)。
配信開始しても何も開かない config.json の youtube.channel が間違っている、または YouTube 側の反映が遅い python main.py --test で確認し、必要なら resolve.timeout_sec を増やしてください。
投稿画面がタイトル空で開く 2分(既定値)以内にライブ情報を取得できず fallback が動いた 手動でタイトルを入力してください。resolve.timeout_sec を増やすと解決する場合があります。
X のログイン画面が開く ブラウザで X にログインしていない ブラウザで X にログインしてから、もう一度お試しください。
「config.json が見つかりません」と表示される 手順4(設定ファイルの作成)が未実施 手順4を行って config.json を作成してください。
「設定エラー」と表示されて終了する config.json の内容に誤りがある 表示されたメッセージに書かれている項目を修正してください。手順4の「JSON の書き方の注意」も参照してください。
同じ配信で2回目の投稿画面が開かない 仕様です(同じ配信では1回だけ開きます) state.json を削除すると、もう一度開くようになります。

12. 制限事項

  • 最後の投稿ボタンは手動です(自動投稿はしません)。
  • ブラウザで X (Twitter) にログインしている必要があります。
  • YouTube のページ構造が変わると取得に失敗する可能性があります。その場合は fallback_open_when_unresolved が true であれば、タイトル空・チャンネルの /live URL で投稿画面が開くので、手動で内容を修正してください。
