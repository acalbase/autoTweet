1. これは何?

OBS で配信開始を押すと、告知ツイートの下書き画面が自動で開きます。ポストを押すだけです。

  • できる: タイトルと URL 入りの下書きが自動で開く
  • できない: ポストボタンは自分で押す

2. 仕組み(図1)

OBS の配信開始を検知 → YouTube から配信タイトルを取得 → X の投稿画面を開く、をこのツールがバックグラウンドで行います。

※画面はイメージです。実際の表示とは異なる場合があります。

3. 必要なもの

  • Windows 10 / 11
  • OBS 28 以上
  • ブラウザで X にログイン済み
  • 自分の YouTube チャンネルの URL

インストール不要(PowerShell スクリプトとして動作します)。

4. 手順1: フォルダを置く

  • youtube-live-tweet フォルダを、好きな場所(デスクトップやドキュメントなど)に置きます。

※画面はイメージです。実際の表示とは異なる場合があります。

5. 手順2: OBS の WebSocket を有効化

OBS の WebSocket(配信状態を外部に伝える通信機能)を有効にすると、配信開始をこのツールが検知できるようになります。

  1. OBS のメニューから 「ツール」→「WebSocket サーバー設定」を開きます。
  2. 「WebSocket サーバーを有効にする」にチェックを入れます(下図の赤枠部分)。
  3. サーバーポートは既定の 4455 のままで構いません。
  4. 「認証を有効にする」をオンにした場合は、「サーバーパスワード」欄に表示されているパスワードを覚えておきます。

※画面はイメージです。実際の表示とは異なる場合があります。

ヒント
パスワードを設定した場合は、次の手順3で作成する config.json の obs.password にそのパスワードを書き込みます。パスワードを設定していない場合は空文字 "" のままで構いません。ポートは 4455 のままであれば obs.port も変更不要です。

6. 手順3: 設定ファイルを作る

  1. エクスプローラで powershell フォルダを開きます。
  2. config.example.json を右クリックし、「コピー」→ 同じフォルダ内に「貼り付け」します(config.example.json のコピー のようなファイルができます)。
  3. そのコピーを右クリックして「名前の変更」を選び、config.json に変更します。
  4. config.json をメモ帳などのテキストエディタで開き、内容を編集します。
{
  "obs": { "host": "localhost", "port": 4455, "password": "" },
  "youtube": { "channel": "@your_handle" },
  "tweet": { "text": "配信はじめました！\n{title}", "include_url": true },
  "resolve": { "retry_interval_sec": 5, "timeout_sec": 120 },
  "fallback_open_when_unresolved": true
}
項目説明
obs.host / obs.portOBS WebSocket サーバーのホスト・ポート。通常は変更不要(ポートは手順2で確認した番号)。
obs.passwordOBS WebSocket サーバーのパスワード。手順2で設定していなければ空文字 "" のまま。
youtube.channel監視対象チャンネル。@handle 形式、または UC... のチャンネルID形式。調べ方は下記参照。
tweet.text投稿文のテンプレート。{title}(配信タイトル)・{url}(配信URL)のプレースホルダが使えます。
tweet.include_urltrue の場合、投稿画面の URL カードに配信URLを渡します(text 内の {url} にも展開されます)。
resolve.retry_interval_secYouTube 側の反映待ちのリトライ間隔(秒)。
resolve.timeout_secリトライを諦めるまでの時間(秒)。
fallback_open_when_unresolvedタイムアウトしてもライブ情報が取得できなかった場合に、タイトル空・チャンネルの /live URL で投稿画面を開くかどうか。

youtube.channel の調べ方

ブラウザで自分の YouTube チャンネルページを開き、アドレスバーの URL を確認します。 https://www.youtube.com/@xxxx のような形になっているので、@xxxx の部分をそのまま youtube.channel に書きます。

※画面はイメージです。実際の表示とは異なる場合があります。

注意
  • JSON ファイルは書き方のルールが厳密です。最後の項目の後にカンマを付けないこと、true / false にはクォート(引用符)を付けないことに注意してください("true" ではなく true)。
  • 改行を入れたい場合は \n と書きます(tweet.text の例を参照)。
  • tweet.text の中で { や } をプレースホルダではなく普通の文字として使いたい場合は、{{ と }} のように2重にして書いてください。

投稿文テンプレートの例

tweet.text はゲーム配信らしい文面に自由に変えられます。よく使われそうな3パターンを挙げます。

タイプtweet.text の値
シンプル 配信はじめました！\n{title}
ハッシュタグ付き 🔴 配信開始！\n{title}\n#ゲーム実況 #YouTubeLive
参加型 【参加型】配信はじめました！\n{title}\n参加希望はコメントで！

{title} には YouTube 側で設定した配信タイトルがそのまま入ります。たとえば配信タイトルを 「【エルデンリング】初見プレイ #12 ラスボスまで行く」にしておけば、ゲーム名やシリーズ番号を tweet.text 側に毎回書き直す必要はありません。ハッシュタグも問題なくそのまま投稿文に入ります。 投稿画面は開くだけで投稿はされないので、ポストする前に自由に書き足しても構いません。

7. 手順4: 動作確認

  • 実際に配信中の状態で、test.bat をダブルクリックすると、1回だけ投稿画面が開きます(OBS を起動していなくても試せます)。

※画面はイメージです。実際の表示とは異なる場合があります。

ヒント
配信していない状態で test.bat を実行した場合、resolve.timeout_sec(既定120秒=2分)だけ待ってからライブ情報が取得できず、fallback_open_when_unresolved が true ならタイトル空・チャンネルの /live URL で投稿画面が開きます。

8. 手順5: 配信の流れに組み込む

配信開始から投稿画面が開くまでの時間は YouTube 側の反映に左右されます。

手順

  1. start-hidden.vbs をダブルクリックします。画面は何も表示されませんが、バックグラウンドで常駐が始まります(手順6を済ませていれば PC 起動時に自動で始まります)。
  2. いつも通り OBS でゲームを起動し、配信を開始します。
  3. 数十秒後に、自動でブラウザに投稿画面が開きます。
  4. 内容を確認して「ポストする」を押します。

同じ配信では、投稿画面は1回だけ開きます。

止めるときは stop.bat をダブルクリックします。

様子を見たい・デバッグしたいときは、画面が表示される start.bat を使うか、常駐中に自動生成される live-tweet.log をメモ帳などで開いて確認してください。

すでに常駐している状態でもう一度 start-hidden.vbs(または start.bat)を実行してしまった場合、二重起動は自動的に防止されます(2つ目は起動後すぐに終了します)。

9. フルスクリーンのゲーム中に投稿画面が開いたら

注意
投稿画面が開くとブラウザが前面に出るため、フルスクリーン(排他)モードで動かしているゲームは最小化されることがあります。プレイ中に画面が急に切り替わって驚かないよう、事前に対策しておくのがおすすめです。
  • ゲームを「ボーダーレスウィンドウ」設定にする — 多くのゲームにあるウィンドウモードの一つで、見た目はフルスクリーンのままですが、Alt+Tab などで他のウィンドウに切り替えても表示が崩れません。
  • モニターが2枚あるなら、ブラウザを2枚目のモニターに置く癖をつける — 既定のブラウザは、最後に閉じたときのウィンドウ位置で次に開きます。一度2枚目のモニターに移動しておけば、以降もそちら側で開くようになります。
  • 配信開始からゲームを始めるまでに「まもなく開始」画面を1分ほど挟む — その待機時間の間に投稿画面が開いてポストを済ませてしまえば、ゲーム本編に入ってから画面が切り替わる心配がありません。

投稿画面をうっかり閉じてしまっても大丈夫です。test.bat を実行すれば、もう一度投稿画面を開けます。

10. 手順6(任意): Windows 起動時に自動開始

  1. Win + R を押し、shell:startup と入力して Enter を押します。スタートアップフォルダが開きます。
  2. start-hidden.vbs を右クリックして「ショートカットの作成」を選びます。
  3. 作成されたショートカットを、開いておいたスタートアップフォルダに移動(配置)します。

これで Windows にログインするたびに、自動的にバックグラウンドで常駐が始まります。

11. 困ったときは

症状原因対処
何も起きない・配信を開始しても投稿画面が開かない 常駐していない / OBS の WebSocket が無効 / ポート・パスワードが違う 常駐していない場合は stop.bat を実行後に start-hidden.vbs を再実行してください。それ以外は live-tweet.log を確認し、手順2の設定を見直してください。
ログに「OBS WebSocketに接続できません」が続く OBS が起動していない、または WebSocket が無効/ポート・パスワードが違う OBS を起動していない間は正常な表示です(起動すれば自動的に接続します)。それでも続く場合は手順2の設定を確認してください。
投稿画面がタイトル空で開く 最大待ち時間(resolve.timeout_sec)以内にライブ情報を取得できず fallback が動いた 手動でタイトルを入力してください。resolve.timeout_sec を増やすと解決する場合があります。
X のログイン画面が開く ブラウザで X にログインしていない ブラウザで X にログインしてから、もう一度お試しください。
「config.jsonが見つかりません」と表示される 手順3(設定ファイルの作成)が未実施 手順3を行って config.json を作成してください。
「設定エラー」と表示される config.json の内容に誤りがある 表示されたメッセージに書かれている項目を修正してください。手順3の「JSON の注意」も参照してください。
同じ配信で2回目の投稿画面が開かない 仕様です(同じ配信では1回だけ開きます) state.json を削除するか、test.bat でもう一度動作確認できます。
「WindowsによってPCが保護されました」と表示される Windows のセキュリティ機能による警告 「詳細情報」をクリックし、「実行」を選んでください。
二重に起動したかもしれない すでに常駐している状態で再度起動を試みた 2つ目は自動的に終了するため問題ありません。心配な場合は stop.bat を実行してから start-hidden.vbs を実行し直してください。
ゲームが最小化された・画面が切り替わった 投稿画面が開いてブラウザが前面に出たため 「フルスクリーンのゲーム中に投稿画面が開いたら」の対策(ボーダーレスウィンドウ化など)をお試しください。
投稿画面が開いたのに気づかなかった ゲームが前面のままで、投稿画面が背後で開いていた タスクバーでブラウザのアイコンを確認してください。配信開始直後に「まもなく開始」などの待機画面を挟む運用にすると気づきやすくなります。
配信タイトルを直前に変えたのに古いタイトルが出た YouTube 側にタイトルが反映される前に情報を取得してしまった ポストする前に手動でタイトルを直してください。配信を始める前にタイトルを確定させておくと発生しにくくなります。

12. 制限事項

  • 最後の投稿ボタンは手動です(自動投稿はしません)。
  • ブラウザで X (Twitter) にログインしている必要があります。
  • YouTube のページ構造が変わると取得に失敗する可能性があります。その場合は fallback_open_when_unresolved が true であれば、タイトル空・チャンネルの /live URL で投稿画面が開くので、手動で内容を修正してください。
  • OBS を再インストールした場合は、手順2の WebSocket 設定をやり直す必要があります。
  • ゲームのアンチチート等が理由でブラウザ起動を妨げることはありませんが、フルスクリーン(排他)モード中の画面切り替わり方はゲームによって異なります。
